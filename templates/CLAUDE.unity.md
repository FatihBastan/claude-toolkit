## Working with Claude in this repo

- For "where is X used" / "which prefab references Y" questions, spawn the **Explore subagent** — Unity references span `.cs`, `.unity`, `.prefab`, `.asset`, and `.meta` files; doing it inline drowns the main context.
- **Never read `.meta` files** unless explicitly debugging a GUID/import issue. They're auto-generated and noisy.
- **`.unity` and `.prefab` are large YAML.** Use ranged reads (offset/limit) when you need to inspect — never slurp a whole scene.
- For runtime behavior changes, run the relevant PlayMode test or open the scene in editor; static analysis is not enough for Unity.
- The `Library/` folder is regenerated by Unity on open. Never read it. If a build is misbehaving, deleting it is a legitimate first move (it'll rebuild on next open, ~minutes).
- If `notes/daily/` exists, read the latest entry on session start and log to today's file at session end. (See `session-log` skill.)

## Don't read

These paths burn input tokens without helping accuracy:

- **Generated / cache:** `Library/`, `Temp/`, `obj/`, `Logs/`, `UserSettings/`, `MemoryCaptures/`
- **Build output:** `Build/`, `Builds/`, `*.apk`, `*.aab`, `*.ipa`
- **Auto-generated by Unity:** `*.csproj`, `*.sln`, `Assembly-*.csproj`
- **Meta files (everywhere):** `*.meta` — auto-generated GUID + import settings; skip unless debugging a missing reference
- **Lockfiles:** `Packages/packages-lock.json`
- **Binary content:** `*.fbx`, `*.png`, `*.jpg`, `*.psd`, `*.tga`, `*.wav`, `*.mp3`, `*.ogg`, `*.anim` (read as YAML only if needed)
- **IDE noise:** `.idea/`, `.vs/`, `.vscode/`
